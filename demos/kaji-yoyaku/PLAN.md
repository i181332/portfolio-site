# 家事代行サイト 予約・決済デモ 制作計画（八王子・高尾）

## Context

ココナラの公開依頼で、八王子・高尾の新規家事代行サービスのサイト制作（33,000円税抜）を提案中。クライアントは前向きで、**10月24日（土）までに「スタッフを選ぶ→空き時間を選ぶ→決済する」をスマホで試せるデモURL**を送ると約束している。デモで納得してもらえれば正式依頼に進む。

本番は WordPress + Square予約プラス（カード事前決済）だが、Square予約にはお客様側のテストモードがないため、デモは **独自の予約画面 + Stripe テストモードの Payment Link** で作る。デモは「操作の流れ」と「本番サイトの品質・デザイン」を見せて契約を取るためのもの。**見た目の説得力が成約を左右する**ので、デザインは本番同等の完成度を目指す。配色・書体・部品・文言は本番 WordPress に引き継げるよう設計し、README に引き継ぎメモを残す。

ユーザー確認済みの方針：
- 置き場所：このリポジトリ内 `demos/kaji-yoyaku/`。公開は Cloudflare Pages の Git 連携（ユーザー側操作）
- データ保存：localStorage のみ（端末間で共有されないことをデモ画面に明記）
- 範囲：トップページ + 予約フロー + 管理画面
- 構成：**複数ファイルの静的サイト**（ビルド不要）。要件7章の「HTML 1ファイル」は制作者側の当初案で、クライアントの制約ではないため、リッチさと WordPress への部品移植を優先して変更
- **UI 品質の要求（ユーザー指示）**：リッチで、AI生成感・テンプレ感のないデザイン。高齢者が迷わず操作でき、同時に若い世代（高齢の親を持つ家族）が「ここに任せたい」と感じる信頼感を出す

## 守ること（要件8章）

- 制作者の連絡先（メール・電話・LINE・SNS）をデモに一切出さない
- 「ご提案用のデモ」「実際の請求はありません」を常時表示（画面下部の細い帯）。店名・スタッフは架空
- `noindex` を付け、検索に載せない
- 検索順位保証や実績を匂わせる文言を入れない。保険加入など未確認の事実は断定しない

## デザイン計画

### 2つの読者を同時に満たす設計思想
- **高齢の利用者本人**：電話で予約するのと同じ順番で、1画面で決めることを少なくする（担当と日時だけは、写真と○×を見比べられるよう同じ画面）。大きな文字と押しやすいボタン。いつでも戻れる。急がせない
- **家族（30〜50代、スマホ/PC）**：余白、書体、料金の明快さ、「人」が見えること、規定の明示で判断する。彼らが**代理で予約する**導線を正面から用意する（「ご家族の方が代わりに予約」）

### 主題から引き出す視覚言語
八王子・高尾＝杉と山の緑、朝の光、手入れされた台所と窓辺。「清潔・安心・親しみ」を、**手元と光の写真**、**深い緑の品のある色**、**明朝で大きく置いた人の名前**で表現する。業者感ではなく「信頼できる近所の人」の温度。

### 主役は1つ：○×の空き状況
駅や病院の空席表の文法。クライアント自身の言葉「空き○×」。**トップの最初の画面に、今日から3日分の実際の空き（localStorage と連動した縮小版）を置き、タップでそのまま予約フローへ入る。** 写真はその下の帯に下げる。予約フロー3手順目では同じ○×を大きく使う。ここだけが画面で一番強い要素になるよう、周りを静かにする。

### トークン（CSS カスタムプロパティとして定義し、本番に流用）
- 色
  - `--paper` #FFFFFF 基調。白の面積を広く取り、余白で品を出す（クリーム地は使わない）
  - `--mist` #EEF3EF ごく薄い緑灰。帯や入力欄の面
  - `--ink` #1C2326 本文
  - `--sugi` #1E4A3A 主色。見出し・主ボタン・フッター・スタッフ名の色面
  - `--sugi-deep` #143428 押下・ホバー、濃い帯
  - `--wakaba` #2F7E52 「空き○」・完了
  - `--ochre` #B9802A **非テキスト専用**（選択中の枠の塗りと線）
  - `--ochre-text` #8A5E1C 価格の数字など**文字に使う時のみ**（白地で約5:1）
  - `--mute` #5F6B6E 補足文、「予約済み×」
  - 実装中に1回、「黄土を外して杉緑の濃淡＋若葉の3色」案と並べて比較し、介護・和モダン系サイトの定番に見えるなら黄土を外す
- 書体（2系統、役割を明確に分ける）
  - **明朝：Shippori Mincho B1** はトップ最初の画面の大見出しと店名のロゴだけ（字間 0.04em まで）。手順タイトル・小見出し・スタッフ名は BIZ UDPGothic 太字・字間0（利用者の指示 2026-10-22：明朝が読みにくい）。見出し書体は `--font-heading` 1つで切替
  - **本文・UI：BIZ UDPGothic**（UD フォント。ボタン、入力欄、○×、注記など「操作するもの」すべて）。代替 `"Hiragino Sans", "Yu Gothic", sans-serif`
  - `font-display: swap`、`preconnect`、必要ウェイトのみ読込（明朝 1、ゴシック 2）
  - 本文 18px / 行間 1.9、ボタン 20px 太字、手順見出し 26〜30px、トップ見出し 32px（スマホ）〜 48px（PC）
  - 数字（料金・時刻）は BIZ UDPGothic 太字で大きく、「円」「時」は小さく
- レイアウト
  - スマホ先行。予約フローは最大幅 520px の1カラム。上部固定は**「戻る」と「手順 n / 4」の2要素だけ**。文字サイズ切替は上部右端に小さく、デモ注記は画面下部の細い帯
  - トップは PC で2カラム（左：見出しと○×、右：写真）、スマホで縦積み。左揃え、行長 35〜40 字以内
  - 面は「白地」「薄緑の帯」「濃緑の帯」の3種。**カードを並べない**：スタッフ・できること・ご家族向け項目は「左に色面か写真、右に文」の行として積み、区切りは余白と1本の罫のみ
  - 角丸は2段階（ボタン 12px、写真と色面 20px）。影なし
- 構造装置は意味がある所だけ：番号は予約手順にのみ使う。中黒区切り、英大文字ラベル、矢印記号、影、グラデーション、ヒーローの「大きな数字＋小ラベル」は使わない
- 動き：読込時の演出なし。利用者の操作に答える動きだけ（○を選ぶと塗られる、確定で×へ切替、手順の切替は短い横スライド）。`prefers-reduced-motion` で全停止

### ○× のスマホ上の形（確定）
```
[< 戻る]              手順 2 / 4
担当（丸い写真のタイル4つを横1列。どなたでも／山本／小林／森田）
選んだ担当の紹介（2〜3行）
日にちを選ぶ（横スクロール）
┌────┬────┬────┬────┬────┐
│25土│26日│27月│28火│29水│ …
│ ○ │ × │ ○ │ ○ │ ○ │  ← その日に1枠でも空きがあるか
└────┴────┴────┴────┴────┘
開始時刻を選ぶ（縦1列）
午前 9時   ○ 空き
午前10時   ○ 空き
午前11時   × 予約済み
午後 0時   × お休み
午後 1時   ○ 空き              ← 選択中は黄土の塗りと太い線
午後 2時   × 時間が足りません
```
- 時刻の1行は高さ 64px。○×は直径 40px の円＋文字。横に並べない（8枠×56px は 390px に収まらない）
- 「どなたでもよい」選択時も同じ縦1列。○の右に「担当：山本」のように最も早く空いている人を自動で表示する
- トップの縮小版は「日付3列 × スタッフ3行」の表で、各セルに ○ の数（「○ 4枠」）か「×」。**最短の2時間利用を前提**とし、その旨を小さく注記。セルをタップすると担当と日付を引き継いで手順2（利用時間）から始まる
- 文字サイズ切替はトップ最上部の1行に置き、予約フローの固定ヘッダーは「戻る」「手順 n / 4」の2要素を守る

### 写真・素材（方針を確定）
- **スタッフは顔写真を見ながら選べるようにする（利用者の指示 2026-10-22）。** Pexels の素材写真を使い、「写真は素材です（本番はご本人）」と画面に明記する。写真が無い時は杉緑の円に姓の1字
- 写真は**手元・道具・光**に限定：絞った布巾、やかんと窓辺、畳の目、窓越しの緑、拭き上げた床。Unsplash / Pexels から WebP 化してリポジトリに保存し、出典を README に記載。点数は 4〜5 枚、初回表示の総容量 1.2MB 以内
- **着手後 1 時間で候補を確定**。基準に合う写真が集まらなければ、色面と余白だけで構成する案に切り替える（写真が無くても成立する設計にしておく）
- アイコンは最小限（電話、戻る、チェック）。線幅 2px の自作 SVG

### コピーの方針
- 利用者の言葉で、具体的な作業と条件を主語にする。「○○で、○○を。」型の広告コピーは禁止
- トップ見出し（確定）：**「掃除機がけと台所の片づけ。2時間からお伺いします。」** 副文：「八王子・高尾のご自宅へ。1時間3,500円。」
- ボタンは起きることをそのまま書く：「空き状況を見て予約する」「この時間で予約する」「カードで支払う（テスト）」。完了は「ご予約を承りました。」
- 家族向けの見出しは平叙で：「ご家族の方に知っていただきたいこと」。保険・身分証などは「掲載予定（本制作時に確認）」が分かる形

### テンプレ回避チェック（制作前と批評ループで再確認）
- クリーム地+テラコッタ、黒地+蛍光色、SaaS カード一式、新聞風ハイライン、英大文字ラベルは使わない
- 見出しの一語だけ色替えしない
- スクリーンショットを他の家事代行・介護サイトと並べて「見分けがつくか」を1回自問し、1つ装飾を外す

## 画面仕様

### 画面構成（3ページ。予約フロー内の手順はハッシュ + `history.pushState`。端末の「戻る」も画面の「戻る」と同じ動作）

**`index.html` トップページ**
1. 最初の画面：明朝の見出し「掃除機がけと台所の片づけ。2時間からお伺いします。」＋ 副文 ＋ **今日から3日分の○×縮小表（タップで予約へ）** ＋ 主ボタン「空き状況を見て予約する」＋ 副リンク「お電話で予約する（デモのため番号は非掲載）」。PC では右に写真1枚
2. 薄緑の帯：できること（掃除機がけ／台所・水まわり／お部屋の片づけ。左に小さな写真、右に文の行）
3. 料金：2/3/4時間の3行表。数字を大きく（`--ochre-text`）、「交通費・用具代は本制作時に確認」の一文
4. ご利用の流れ：3手順（ここだけ番号あり）。予約 → 当日訪問 → 作業後に報告
5. 担当スタッフ：3名（名前の色面・得意なこと・勤務曜日の行）。「担当を選んで予約」へ
6. ご家族の方に知っていただきたいこと：代理予約できること、同じ担当の継続、作業後の報告、キャンセル規定、身分証・保険（掲載予定の注記）
7. 濃緑のフッター：屋号（架空）、対応エリア、特商法・プライバシーポリシー（モーダル「本制作時に正式文面を作成」）
8. 画面下部の細い帯：デモ注記（常時）

**`booking.html` 予約フロー（4手順。担当の既定は「どなたでもよい」）**
1. 利用時間を選ぶ（2/3/4時間。金額を大きく併記）
2. 担当と日時を1画面で選ぶ（上段に写真つきの担当タイル、下段に日付の帯と時刻の縦1列。担当を替えると○×がその場で切り替わる。7日×時刻の大きな表は画面に収まらないので使わない）
3. お客様情報（お名前・電話・ご住所・ご要望。**「ご家族の方が代わりに予約」切替**で利用者名と予約者名・連絡先を分ける。入力欄は高さ 56px 以上、未入力は欄の直下に文章で案内）
4. 内容の確認（日時・担当・金額・住所を文章で読み上げる形式）→ 「カードで支払う（テスト）」。Stripe 画面は本番と見た目が異なる旨を一文
- 完了画面：明朝「ご予約を承りました。」、予約番号、日時、担当、金額、「この枠は予約できなくなりました」、「管理画面を見る」

**`admin.html` 管理画面**（認証なし。「本番では Square予約の管理画面になります」と明記。フロー画面と同じ品質）
- 必須：予約一覧（日付順。状態：支払い済み／決済待ち／取り消し。取り消しで枠が○に戻る）、スタッフの休み設定（スタッフ×日付のトグル、予約画面に即反映）、デモデータを初期状態に戻す
- 時間が余れば：今週の空き状況（スタッフ別○×一覧）

### 高齢者向け UX の具体策
- 文字サイズ切替「標準／大きく」を常設（localStorage に記憶）。「大きく」でも横スクロールが出ないレイアウト
- 決めることは1画面に少なく（担当と日時の画面を除き1つ）、選択肢は最大4つ、選んだ内容を次画面の上部に小さく残す
- 「戻る」は常に左上の同じ位置。端末の戻る操作にも同じ応答
- 時刻は「午前10時」「午後2時」、日付は「10月25日（土）」表記
- ○×は記号と文字（空き／予約済み）を併記。色だけに頼らない
- タップ領域 56px 以上、コントラスト 4.5:1 以上、`:focus-visible` の輪郭、`aria-live` で手順切替を通知

### データ（localStorage、キー接頭辞 `kajiDemo.`）
- `staff[]`：id, name, intro, skills[], workDays[], start, end
- `bookings[]`：id（例 `A-1025-1`）, staffId, date, start, hours, customer{name, phone, address, notes, proxy?{name, phone}}, amount, status(`pending`|`paid`|`cancelled`), createdAt, **expiresAt（pending のみ、作成から15分）**
- `daysOff[]`：{staffId, date}
- `prefs`：fontScale
- 初期シードは今日を基準に相対生成（既存予約と休みを数件入れ、最初から×が混ざる状態）

### 空き判定
枠（開始 t、利用 h 時間）が○になる条件：勤務曜日内、休みでない、t+h ≤ 勤務終了、過去でない、**有効な予約（`paid`、または期限内の `pending`）**と重ならない。期限切れ `pending` は空き判定から除外し、管理画面では「期限切れ」として表示する。

### Stripe 連携
- `js/config.js` に Payment Link URL を3本（2/3/4時間）置く。ユーザーが Stripe ダッシュボードで作成して貼る
- 支払いへ進む時：予約を `pending`（15分期限）で保存 → `pendingId` を保存 → `link?client_reference_id=<予約ID>` へ遷移
- Stripe 側の完了後リダイレクト先は **`https://<pages>.pages.dev/booking.html?paid=1&session_id={CHECKOUT_SESSION_ID}`**（3本とも同じ）
- 戻った時：`?paid=1` を検知 → `pendingId` の予約を `paid` にして完了画面。**15分の期限を過ぎて戻った場合も支払いは成立しているので `paid` にする**。他の予約と重なっていれば管理画面で「重複」と表示（セッションIDの末尾を参考表示）→ `history.replaceState` でクエリ除去
- **支払い中断への対応**：Payment Link にはキャンセル戻り先がないため、再訪時に `pendingId` が `pending` のままなら「お支払いが終わっていません」画面を出し、「支払いに進む」「この予約を取り消す」を選べる。期限切れなら自動で枠を解放し、その旨を表示
- **フォールバック**：URL 未設定なら、デモ内の「テスト決済画面（Stripe未接続）」で同じ流れを再現。Payment Link 作成前でも通し検証できる
- README に「`?paid=1` を直接開くと支払い済み扱いになるのはデモの簡略化」と明記

## 作業手順

4. **デザイン批評ループを2回以上**：Playwright でスマホ（390×844）と PC（1440 幅）のスクリーンショットを撮り、テンプレ感・余白・書体サイズ・写真の収まり・黄土色の要否を自分で見て修正する
5. `README.md` を作成
6. 検証（下記）→ コミット・push。未追跡の `.claude/skills/frontend-design/` も同ブランチに含める（不要なら指示があれば `.gitignore` に回す）
7. ユーザーへ：Cloudflare Pages 接続 → 公開URL確定 → Stripe の Payment Link 作成（遷移先に公開URL）→ URL 3本を私に渡すか `CONFIG` に貼る → 再 push → iOS Safari 実機で通し確認 → 10/24 までに送付

## 検証方法

- ローカル静的配信（`python3 -m http.server`）＋ Playwright（同梱 Chromium、`executablePath: /opt/pw-browsers/chromium`）
- 通しシナリオの自動化：予約 → 同じ枠が × → トップの縮小表にも反映 → 管理画面に表示 → 取り消し → ○ に戻る → 休み設定 → 予約画面で ×。「どなたでもよい」の自動割当、代理予約の切替、文字サイズ切替の記憶
- 決済まわり：`?paid=1` で戻った時の確定、`pendingId` 無しの案内、`pending` のまま再訪した時の中断画面、15分経過での枠解放、Payment Link 未設定時のフォールバック
- 端末の戻る（`popstate`）が画面の「戻る」と一致すること
- `prefers-reduced-motion`、キーボードのみでの完走、「大きく」＋ブラウザズーム200%で横スクロール無し・タップ領域維持、コントラスト値（`--ochre-text` 含む）、画像の総容量
- 制作者の連絡先・実名が無いことを grep で確認
