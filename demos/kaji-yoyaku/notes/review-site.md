5秒で文字から「家事代行／掃除・台所と水まわり・片づけ・洗濯／1時間3,500円（2時間から）／八王子、高尾／予約する」は分かる（前回の「何の会社か分からない」は直っている）。ただし「頼みたくなるか」は弱い。写真が若い夫婦の洋風の居間（女性が掃除機、男性はソファでパソコン）で、家事代行のスタッフにも、高齢の方の家にも見えない。誰が来るのかが見えず、電話番号も無い。390 では予約ボタンが3つ同時に出て、利用者に向けていない注記が一番目立つ。

## 指摘（重い順）

### 重大1　「お約束」の家族の代理予約・家族への報告は、削除した自前の予約エンジンの機能が残ったもので、Square 予約で確かめられていない
- 場所：index.html:67-73（お約束）、flow.html:58-64（ご家族が代わりに予約する時）、faq.html「家族が代わりに予約できますか」
- 問題：「お伺い先と、連絡を受ける方を分けて予約できます」「ご報告はご家族の方にも届きます」は、commit f3fbb14 で消した booking.js（自前の予約）の機能。今の予約ボタンは Square 予約（config.js:6）に行く。Square 側でこの入力欄を作った記録は STATE.md・notes/square-setup.md・square-check.md に無い。依頼者が予約ボタンを押して Square の画面を見れば、トップの「お約束」と画面が食い違う
- 同じ型：スタッフの「山本さんで予約する」「この人で予約する」は、config.js:7 の staff（s1〜s3）が空なので店全体の入口へ行く。担当は選ばれていない。お約束の「同じ担当が伺います」も、Square で担当を選べる設定にしたかどうか確かめていない
- 直し案：Square で実際にできることだけを書く。家族の行は「ご家族のお名前で予約し、メモ欄にお伺い先を書いてください」など、Square の画面で実際にできる手順に書き換える。確かめるまでは「本番で確認」にする。担当ごとの入口 URL を Square で作って config に入れるか、ボタンを「予約する（担当は次の画面で選べます）」に変える

### 重大2　電話番号の場所が無く、ヘッダーの「お電話　本番で掲載」が壊れた表示に見える
- 場所：ui.js:139（TEL_TEXT）、1440 の全ページのヘッダー右（灰色の小さな字）、フッター、contact.html の「お電話」の節
- 問題：高齢の本人にとって一番の連絡手段は電話。1440 のヘッダーでは「お電話」「本番で掲載」「文字の大きさ」が灰色の小さな字で並んでいて、電話番号の欄だと読めない。390 では電話が最初の画面に出ず、フッターまで送らないと見つからない。お問い合わせのページでも、電話はフォームの下にある
- 直し案：電話番号は「架空の番号を出さない」という決まりのままで、番号の置き場所だけを形で見せる。例：ヘッダーに太字で「電話 042-XXX-XXXX」と出し、その横に小さく「番号は本番で掲載」と添える。390 は下の固定の段を「予約する｜電話する」の2つに分ける。お問い合わせのページでは、電話の節をフォームより上に置く

### 重大3　最初の画面の写真で、何をしてくれるのか・誰が来るのかが伝わらない
- 場所：index.html:47（assets/work-hero.webp）、site-index-1440-first / 390-first
- 問題：写っているのは、家の住人どうしが過ごしている所に見える。エプロンも訪問の様子も無く、利用者層（高齢の方、和室・畳）とも合わない。1440 では 4:3 に切ったため、右下に葉の切れ端が黒い塊のように残っている。依頼者の批判②「何してくれるのか分かんない」は、文字の上では直ったが、写真ではまだ直っていない
- 直し案：スタッフが訪問先で作業している写真（エプロン姿の女性、和室か台所）に替える。別の手として、最初の画面に3人の顔を小さく並べて「この3人が伺います」を写真で伝える（説明文は足さない）

### 中4　予約ボタンの呼び名が4種類あり、390 の最初の画面に予約ボタンが3つ出る。予約ボタンの注記は依頼者向けの文
- 場所：ヘッダーの「予約する」、最初の画面の「予約する」、画面下の固定の段の「空き状況を見て予約する」（ui.js:170）、top.js:44 の「山本さんで予約する」、site.js:19 の「この人で予約する」、ui.js:131 の注記
- 問題：同じ行き先なのに呼び名が違い、別の物に見える。注記「ここから先は予約システム（Square 予約）の画面です。本番も同じ画面です」の後半は依頼者に向けた説明で、利用者には意味が無い。それが全ページの予約ボタンの下に出て、最初の画面では本文の次に大きい灰色の2行になっている
- 直し案：呼び名を「予約する」に揃える。担当ごとのボタンは「山本さんで予約」に揃える。注記は最初の画面から外し、ページ最後の予約の所に「予約は Square 予約の画面で行います」とだけ書く。「本番も同じ」は「このデモについて」のモーダルに移す

### 中5　事実の食い違い（同じサイトの中で矛盾している）
- 営業時間：フッター・お問い合わせ・会社概要は「午前9時〜午後5時、月曜から日曜」（content.js:43）。しかし日曜に出るのは小林さん（content.js:33、午前9時〜午後3時）だけなので、日曜の午後3時〜5時に伺えるスタッフがいない
- 用具：トップのよくある質問（index.html:140）は「ご自宅の掃除機や洗剤を使わせていただきます」と言い切っている。サービス内容（service.html:47）とよくある質問のページは「ご自宅の物を使うか、持参するかは本番で確認」
- 延長：料金のページとよくある質問は「1時間ごとに3,500円」。一方、流れ（flow.html:41）とよくある質問は「当日に現金のやり取りはありません」で、支払いは予約の時だけ。延長分をどう払うのかが書かれていない
- 税：「1時間3,500円」が税込か税抜か書かれていない（price.html「税の扱い 本番で確認」）。お客に見せる値段は税込の総額で示す決まりがあるので、本番前に要る
- 直し案：営業時間は「日曜は午後3時まで」と書くか、スタッフの出勤表を合わせる。用具はトップも「本番で確認」に揃える。延長は「延長分はその場でカードで」など決まるまで「本番で確認」にする。料金は「（税込）」を前提にしてよいか依頼者に聞く

### 中6　「カード払いを試す（テスト）」が行き止まり
- 場所：index.html:172、price.html:43、flow.html:33 → payment.html。config.js:10 の testLink が空
- 問題：押すと「テスト用の支払い画面を準備中です」のモーダルが出るだけ。明日見せる時、トップの最後の予約の所に、行き止まりのリンクが残る
- 直し案：Stripe のテスト用リンクを入れる。入れられないなら、3か所のリンクを外す

### 中7　1440 で中身が左半分に寄り、トップの後半は写真の無い文字だけの帯が交互に続く。同じ色の帯が2つ続く所がある
- 場所：トップの料金（右半分が空）・よくある質問・対応エリア・お知らせ（index-1440-full の2〜5枚目）。下層ページはほぼ全部（料金の表は幅およそ190px、流れ、エリア）
- 問題：1440 の画面の右 40〜50% が白いまま、下まで続く。トップは「できること」とスタッフの所以外に写真が無く、薄い緑と白の帯が交互に続くだけで、プロの制作会社の家事代行サイト（料金と流れを図や写真と組み合わせる）と並べると素人っぽく見える。さらに service.html（掃除の用具→ご予約）、price.html（そのほかの料金→ご予約）、area.html（エリアの外→ご予約）では薄い緑の帯が2つ続き、境目が無いので1つの節に見える（site-service-1440-full の2〜3枚目で確認）
- 直し案：1440 では料金の表の右に支払いと延長の要点、よくある質問の右に対応エリア、のように2段に組む。続く帯は色を交互にする（ページ最後の予約の帯の前は白にする）

### 中8　よくある質問のページに、開け閉めの印が無い
- 場所：site.css:125（.s-qa__item summary に display: flex）。flex にしたため、ブラウザが出す三角の印が消えている。代わりの ::after も無い（トップの top.css:182 には有る）
- 失敗例：faq-390-full で、10問が太字の行として並ぶだけで、押すと開くことが分からない。高齢の方は押さずに離れる
- 直し案：top.css:168-193 の矢印の規則を共通の CSS に移し、両方のページで使う

### 中9　トップの同じ内容の繰り返しと長さ（390 で 7,785px）
- 「1時間3,500円（2時間から）」が3回（最初の画面、料金、最後の予約）。「同じ担当」が3回（お約束、よくある質問、スタッフのボタン）。「作業の後にご報告」が2回（お約束、流れ）。「高尾周辺に住む」が2回（最初の画面、お約束）
- 「できること」は 390 で写真4枚が全幅で縦に並び、それだけで約1,500px ある
- 直し案：お約束は、重複しない「同じ担当」と（確かめた後の）「ご家族の予約」の2行だけにするか、節ごと無くして流れに含める。390 の「できること」は写真を2列にする。最後の予約の所の料金の行を削る

### 軽微10　見た目の細部
- 見出しが二重：サービス内容→お受けする家事、料金→料金表、ご利用の流れ→手順、お問い合わせ→フォーム、対応エリア→お伺いする地域。h1 のすぐ下の h2 は要らない
- area.html の地区と駅の角丸の枠（site.css:120）は押せるボタンに見えるが、押しても何も起きない。高齢の方は押してしまう。読点区切りの文にするか、地図に替える
- お知らせの罫線：一番上の線（約960px）と各行の下の線（約876px）で長さが違う（index-1440-full の5枚目）
- staff.html の曜日が「月、火、水、金曜」で、最後だけ「曜」が付く（site.js:17）。トップの「出勤日」と、スタッフ紹介の「お伺いする曜日」「お伺いする時間」で呼び名が違う
- 「トップへ戻る」（404）と「トップに戻る」（payment）で言い方が違う
- 390 のスタッフの出勤日が「午前9時〜／午後5時」の所で改行される（index-390-full の4枚目）。曜日と時間を別の行にする

### 抜け（会社のホームページとして足りない物）
- 電話番号の置き場所（重大2）
- 対応エリアの地図（地区の名前だけでは、家族にも本人にも範囲が分からない）
- スタッフ紹介の人柄：名前と曜日だけで、選ぶ手がかりが無い。本人の一言（「本番でご本人の言葉」と添える）や家事の経験年数の欄を、枠として置く
- 料金の税込・税抜（中5）、取り消し料（今は「本番で確認」）。依頼者に先に決めてもらう事柄の一覧として、渡す時に添える
- 屋号の印（ロゴ）が無く、文字だけ。本番では要る物として README に書く

- 料金の計算：2時間 7,000円、3時間 10,500円、4時間 14,000円（top.js:23-28 で CONFIG から計算、price.html と同じ値）
- 最初の画面に、h1「八王子、高尾の家事代行」、作業名、料金、予約ボタン、写真がある（390 と 1440 の両方。主ボタンは 390 の y≈400 にある）
- 決まりで禁止した見た目：グラデーション・影・英大文字・text-transform は CSS に無い。中黒と「→」も画面に無い。手順の番号は flow.html だけ（手順なので決まりの範囲内）
- 全13ページに noindex がある。デモ注記の帯が全ページに出ている。フッターに会社概要・特定商取引法に基づく表記・プライバシーポリシーへのリンクがある。404 にトップへのリンクがある
- 予約ボタンの行き先：店全体の Square の URL が入っている（config.js:6）
- 保険・実績・お客様の声は書かれていない（よくある質問の保険も「本番で確認」）
- 見出しの横・下に説明文を足す書き方（依頼者の批判①の型）は、トップではほぼ無くなっている。残っているのは flow.html の家族の節の「離れて暮らすご家族の代わりに予約できます。」だけ

## 親の判断（直し方。2026-10-23）
1. 家族の機能：Square でできることだけ書く。「ご家族が代わりに予約できます（予約の画面で、お伺い先の住所を入れます）」。「連絡を受ける方を分けて」は消す。報告は店の約束として「作業の後に、終えた所をお伝えします。ご希望があればご家族にも」まで（仕組みの話をしない）
2. スタッフ別のボタン：担当を選んだ入口にならないので「◯◯さんで予約する」「この人で予約する」をやめ、全部「予約する」に統一。スタッフの欄に1回だけ「担当は予約の画面で選べます」
3. 電話：架空の番号は出さない。ヘッダー（1440）とスマホのメニュー・トップの締めに、点線の枠で「お電話番号（本番で掲載）」と分かる置き場所を作る（灰色の小さな字にしない）
4. 最初の画面の写真：`work-tidy.webp`（制服のスタッフ2人が寝室を整える＝訪問サービスに見える）に替える。`work-hero.webp` は「掃除機がけ」の写真に回し、`work-vacuum.webp` は使わない
5. 予約ボタンの呼び名は全部「予約する」。注記「ここから先は予約システム（Square 予約）の画面です。本番も同じ画面です」は最初の画面から外し、締めの予約の所に小さく1回だけ「予約は Square 予約の画面で行います」
6. 食い違いの統一：営業時間「月〜土 9時〜17時、日 9時〜15時」。用具は全ページ「本番で確認」に統一（言い切らない）。延長の支払いは「延長分のお支払い方法は本番で確認」。料金に「税込（本番で確認）」
7. 「カード払いを試す（テスト）」へのリンクは、config の payment.testLink が空の間は出さない（payment.html 自体は残す）
8. 1440 の左寄り・同じ色の帯の連続・FAQ の開閉の印は、審査の直し案どおり
9. 文の表の「削る」「短くする」は、上の判断に反しない限り直し案どおり
