# トップページ スマホ版 デザインレビュー（独立）

2026-10-22。対象：`index.html`、`css/top.css`・`pages.css`・`base.css`・`tokens.css`、`js/top.js`。書体の選定は対象外（大きさ・太さ・行間は対象）。
測定：Playwright（chromium）で 390×844・375×667・1440×900 を開き、getBoundingClientRect／getComputedStyle で測った（縦位置は文書の先頭からの px）。画像は末尾。

## 結論（3行）
1. PC では見出し 46px と写真が最初の画面の格を作っているが、スマホでは見出しが 26px に縮み、節見出し（26.3px）・料金の数字（36px）と同格以下になって、ページの階層が平らになる。
2. 余白はトークン上は 4 の倍数で揃っているが、節の上下 72px が PC と同じ値のまま、節の中は PC の2〜4列の組みをそのまま 358px に詰めている。その結果、縦は間延びし（節の境で 168px が空く）、横は窮屈になる（1行 9〜16 字）。
3. 最初の画面では、2段に折れた上部の帯（108px）と下部のデモ帯（36px）が 17% を取る。375×667 では主ボタンが画面の外に出て、○× 表の3行目がデモ帯に隠れる。

利用者の「余白の使い方が下手」は、半分は当たっている（2の縦の間延び）。ただ、一番大きい原因は余白ではなく、見出しの大きさの段がつぶれていること（1）。

## 指摘（重い順）

### 1【重大】スマホで見出しの階層がつぶれ、ページで一番大きい文字が料金の数字になる
- 何が：`css/top.css:37` `font-size: min(var(--fs-display), 100cqi / 13.7)`。1文13字を1行に収めるための上限で、スマホでは 358/13.7 = 26.1px になる。`.hero__title span { display:inline-block }`（`top.css:43`）で2文を2行に固定している。
- 実測（文字の大きさ、px）

| 要素 | 390 | 375 | 1440 |
|---|---|---|---|
| h1 `.hero__title` | **26.1** | **25.0** | 46.1 |
| h2 `.sect__title` | 26.3 | 26.2 | 30 |
| `.price__yen` | **36** | 36 | 36 |
| `.people__name` | 24 | 24 | 24 |
| `.hero__lead` | 20 | 20 | 20 |
| 本文 | 18 | 18 | 18 |

  - h1 と h2 の比は 390 で 0.99、375 で 0.96（h1 の方が小さい）。PC では 1.54。
  - h1 と lead の比は 390 で 1.31、PC で 2.31。h1 の箱は 74px、lead の箱は 72px（2行に折れる）で、ほぼ同じ量に見える。lead の行間は 36px（1.8）で、h1 の行間（1.42）より緩い。このため lead の2行が別々の2項目に見える。
  - スマホで一番大きい文字は料金の「7,000」（36px）。PC では h1（46px）が一番大きい。
  - 文字の大きさは 14／15／18／20／24／26.1／26.3／36 の8段あり、20〜26px に4段が詰まっていて、段の差が見分けられない。
- 食い違う仕様：`PLAN.md:51`「トップ見出し 32px（スマホ）〜 48px（PC）」。`tokens.css:39` の `--fs-display` も最小は 32px だが、top.css:37 の min() がそれを 26px まで下げている。
- 原則：視覚の階層（大きさで重要度を表す）。デジタル庁デザインシステムのタイポグラフィ（https://design.digital.go.jp/dads/foundations/typography/）では、見出しの段が 45/36/32/28/26/24/22/20 と定義されている。いまの h1 と h2 は同じ段（26）に重なっている。
- 直し方の案
  - 960px 未満では `.hero__title span` の inline-block を外し、h1 を 32px（2rem）、字間 0.02em にする。「掃除機がけと／台所の片づけ。／2時間から／お伺いします。」と文節で4行に折る（auto-phrase は既に効いている）。増える高さは約 +60px で、指摘3の上部の帯の削減で吸収する。
  - スマホの h2 は `--fs-step` の最小を 1.625rem から 1.375rem（22px）に下げる。h1:h2 は 32:22 = 1.45 になり、PC の比に近づく。
  - `.hero__lead` は 18px にし、`span{display:inline-block}` を外して自然に折る（1〜2行）。h1 と lead の比は 1.78 になる。

### 2【重大】節の縦の余白は PC と同じ値なのに、節の中は PC の多列の組みをそのまま詰めている（縦は疎、横は密）
- 何が：`top.css:17` `.sect { padding-block: var(--space-8) }`（72px）は、画面の幅にかかわらず同じ値。節の中の行は、`top.css:156`（できること：88px の画像＋本文）、`top.css:199-212`（スタッフ：80px の写真＋本文の中に、さらに 7em の dt と dd の2列、`:210`）を、スマホでも横に並べている。
- 実測（390）
  - 節の境では、前の節の最後の行の下 24 ＋ 節の下 72 ＋ 次の節の上 72 で、**168px** が空く（画面の高さ 844 の 20%）。h2 からその節の最初の行までは 24px、行と行の間は 49px（24＋罫1＋24）。比（168:49:24）の順は正しく、近接の原則には沿っている。問題は絶対量。全体の長さは 6076px（7.2 画面分）、PC は 4851px。
  - 1行の字数（幅÷字の大きさで概算）

| 箇所 | 390 | 1440 |
|---|---|---|
| できること 本文（`.tasks__row p`、254px） | **14字**・4行 | 28字 |
| ご利用の流れ 本文（298px） | 16字 | 34字 |
| スタッフ 紹介文（262px） | 14字 | 29字 |
| スタッフ「得意なこと」の dd（**145px**、15px） | **9字**・3行 | 27字・1行 |
| ご家族 dd（全幅 358px） | 19字 | 26字 |

  （仕様 `PLAN.md:55` は「行長 35〜40 字以内」で上限だけを定めている。下限は書かれていない。）
  - 目で見た誤りの例：「得意なこと」は「お部屋の片づ／け」、「お伺いする日」は「金曜　午／前9時〜午後5時」と、語の途中で1〜2字だけが次の行に落ちる（`review-top-390-people.png`）。dd には `word-break: auto-phrase` が無い。できることの本文も「部屋の隅まで掛／け」と語の途中で折れる（`review-top-390-tasks.png`）。
  - スタッフの1行（1人分）は 348〜381px あり、3人で 1085px（1.3 画面）。「この人で予約する」ボタン（358×56、`top.css:212`）は写真の列の下まで全幅に広がり、写真 80px の列と本文の列のどちらにも揃っていない。
- 原則：近接と、1列の構成。Apple HIG Layout「Group related items to clearly express related information or functions. For example, you might use negative space, container shapes, or separator lines to show which elements are related and which are unrelated.」（https://developer.apple.com/design/human-interface-guidelines/layout）。Material 3 window size classes「Compact and medium breakpoints: A single pane works best」（https://m3.material.io/foundations/layout/applying-layout/window-size-classes）。いまは、小さい画面でも大きい画面の入れ子の列を残している。
- 直し方の案
  - `.sect { padding-block: clamp(3rem, 2rem + 3vw, 4.5rem) }`。390 で約 48px になり、節の境は 24＋48＋48 = 120px に縮む。PC は 72px のまま。
  - 640px 未満の `.people__facts > div` は `grid-template-columns: 1fr; gap: 0` にして、dt を上、dd を下に置く。dd と本文の p に `word-break: auto-phrase` を足す。dd の幅は 262px になり、1行 17 字に広がる。
  - 640px 未満の `.tasks__row` は、画像を 4rem（64px）に縮める（本文 278px、約 15 字）か、画像を本文の上に 16:9 で全幅に置く（358px、約 19 字）。
  - `.people__btn` は、スマホでも `grid-column: 2` にして本文の列に揃える。全幅のままにするなら、写真を 64px にして名前と1行に並べ、写真・本文・ボタンを同じ列に積む。

### 3【重大】最初の画面の配分：上下の帯が 17% を取り、375×667 では主ボタンが画面の外に出る
- 何が
  - `top.css:9` `.page-top .topline__shop { display:block }` が、`pages.css:33` の「419px 以下では店名を隠す」を打ち消している。店名 164px ＋ 間 16px ＋ 切替 230px = 410px で 358px に入らず、`flex-wrap` で2段に折れる。
  - `base.css:520-` の `.demo-band` は sticky で、下の 36px を常に覆う。
  - `top.css:33` `.hero { padding-block: 16px 32px }`。
- 実測：390×844 の最初の画面での面積（高さ）の割合

| 区画 | px | 割合 | 1440×900 の場合 |
|---|---|---|---|
| 上部の帯（`.topline`） | 108 | 12.8% | 73（8.1%） |
| 見出し＋lead（余白込み 124→278） | 154 | 18.2% | |
| ○× の台（`.mini`） | 399 | **47.3%** | 407（45.2%、横は 544/1120） |
| ボタン＋電話（708→812） | 104 | 12.3% | |
| デモ帯 | 36 | 4.3% | 36 |
| 上下の帯の合計 | 144 | **17.1%** | 109（12.1%） |

  - 390：電話の文字リンク（764〜812）の下 4px がデモ帯（808〜）に重なる。
  - 375×667：主ボタン（y=705〜761）は画面の外。デモ帯（631〜667）が森田の行（セル 568〜644）を半分覆い、名前の「森田」が切れる（`review-top-375-first.png`）。見えている中身の高さは 667−108−36 = 523px しかない。
  - 店名は 14px で、隣の「文字の大きさ」（15px）より小さい。押せる高さは 27px（指摘6）。
- 食い違う仕様：`PLAN.md:33`「トップの最初の画面に、今日から3日分の実際の空き（…）を置き、タップでそのまま予約フローへ入る」。375 では主ボタンが画面の外にあり、○× 表の3行目（森田）はデモ帯に半分隠れる。○のマス自体はリンクなので、1〜2行目（山本・小林、y≈400〜558）から予約に入る道は最初の画面に残っている。崩れているのは配分で、導線そのものは切れていない。
- 原則：最初の画面に主の行動を置くこと。Material 3 の compact の余白は「Margins are 16dp from the leading and trailing edge of the window.」（https://m3.material.io/foundations/layout/applying-layout/compact）。左右の 16px は合っている。問題は縦の配分。
- 直し方の案
  - 420px 未満では「文字の大きさ」の文字を `visually-hidden` にして（radiogroup の名前は aria-labelledby のまま残す）、店名と切替を1段に置く。切替は 230px から約 120px（ボタン2つ＋枠）になり、164＋16＋120 = 300px で入る。上部の帯は 8＋56＋8＋罫1 = 約 73px になり（−35px）、PC の帯（73px）と同じ高さになる。
  - `.hero` の上は 16px から 24px にし、帯との間を少し取り戻す。下は 32px のまま。
  - 指摘4の○× 表の縮小（約 −36px）と合わせて、375×667 で主ボタンの下端が 631px より上に来ることを目標にする。値は直した後に必ず測り直すこと。指摘1の h1 4行（+60px）とは取り合いになるため、375 で主ボタンを入れることを優先するなら、h1 は 28px・3行（「掃除機がけと台所の片づけ。」が 358px に入らない場合は文節で折る）を次の候補にする。

- 色面：390 では、薄緑の台（.mini、〜693）と次の薄緑の帯（できること、844〜）の間に、主ボタンだけを載せた白い帯（151px）が挟まる。薄緑・白・薄緑が短い間隔で交互に来るため、ボタンが色面の「すき間」に置かれたように見える。PC では次の帯が最初の画面の外（882〜）にあるので、この重なりは見えない。案：スマホでは台の下の余白を詰め、ボタンを台のすぐ下 16px に置く。指摘3の帯の削減で、次の帯の頭が少し見えるようにする。

### 4【中】○× 表：9マスのうち6マスが「×＋空きなし」で、主役の○が埋もれる。小さい字は 14px の下限に張り付いている
- 何が：`js/top.js:50-51` は、空きの無いマスにも「×」の円と「空きなし」の文字を置く。`top.css:97` `.mini__cell { min-height: 4.5rem }` で、空いているマスと空いていないマスが同じ大きさを取る。
- 実測（390）
  - 9マス中、空きなしは 6 マス。どのマスも 83×72〜76px。
  - 字の大きさ：`.mini__rel`（今日／明日）14px（`top.css:70`）、空きなしの `.mini__count` 14px（`top.css:107`）、`.mini__name` 15px（PC は 18px）、日付 18px、○の数 18px 太字。
  - ○ と × の円はどちらも 30px で、形の大きさに差が無い。空いているマスは枠（2px）だけで区別している。
- 原則：主役の強調（`PLAN.md:33`「ここだけが画面で一番強い要素になるよう、周りを静かにする」）。デジタル庁 DS typography「本文やUIにおいては16 CSS px以上が基準値となります」「14 CSS px未満の大きさの使用は原則として許容されません」。いまは下限そのもの。
- 直し方の案
  - 空きなしのマスは × の円を 20px、`--mute` の線にして、「空きなし」の文字は見た目から消す（aria-label は残す）。空きのあるマスは今のまま。こうすると、目に入るのは○だけになる。
  - 440px 未満の行の高さは `min-height: 3.75rem`（60px）にする。3行で約 −36px。
  - `.mini__rel` と空きなしの文字は 15px（`--fs-small`）に揃え、14px を無くす。

### 5【中】左端が揃っていない（最初の画面で4本、節の行の本文で3本）
- 実測（390、左端の x）
  - 最初の画面：見出し・lead・電話は 16。表の台の中では、表が 24、「今日から3日間の空き」と注記が 32、スタッフの写真が 40。主ボタンの文字は中央揃え。台の内側の左右の余白は 8px（`top.css:49` `padding: 12px 8px`）で、PC の 16px より狭い。
  - 節の行の本文の左端：できること 120（画像 5.5rem＋16）、ご利用の流れ 76（番号 2.75rem＋16）、スタッフ 112（写真 5rem＋16）。スクロールすると、本文の列が 120→76→112 と左右に揺れる。
  - 電話の文字リンクは左寄せ（`top.css:123` `justify-items:start`）なのに、その直上の主ボタンの文字は中央にある。ボタンとの間は 0px（`gap: 0`）。
- 原則：整列（揃いが関係を表す）。Apple HIG Layout の上記の一文。
- 直し方の案
  - 台の中の余白は 440px 未満でも左右 16px（`padding: 12px 16px`）にし、`.mini__title`／`.mini__note` の `padding-inline: 8px` を外して、台の中の左端を 32px の1本にする。
  - 行の左の列は、スマホでは 4rem に揃える（tasks の画像 4rem、steps の番号は 44px の円を 4rem の列の左に置く、people の写真 4rem）。本文の左端は、どの節でも 16＋64＋16 = 96 になる。
  - スマホの電話リンクは中央揃え（`justify-items:center`）にし、ボタンとの間を 8px にする。

### 6【軽微】押せる所の大きさ
- 店名のリンク（`.topline__shop`）は 164×27px。Apple HIG Accessibility の「Minimum control size 44x44 pt」（https://developer.apple.com/design/human-interface-guidelines/accessibility）と、Material 3 の「consider making touch targets at least 48 x 48dp」（https://m3.material.io/foundations/designing/structure）に足りない。WCAG 2.2 2.5.8 の「at least 24 by 24 CSS pixels」は満たす。
- 直し方：`display:inline-flex; align-items:center; min-height: 44px`。

### 7【軽微】料金表は全幅で、「2時間」と「7,000円」が離れすぎる
- `top.css:190` `.price { max-width: 30rem }` は、スマホでは全幅になる。時間は x=16 から始まり、金額は右端 374 に寄る（約 300px 離れる）。行の高さは 76px。
- 直し方：スマホでは `max-width: 20rem` にして、2つの距離を縮める。

## 実データで確かめて合っていたこと
- 横のはみ出しは無い（390／375／1440 とも scrollWidth <= innerWidth）。
- 左右の余白は 390 と 375 で 16px（`.container`／`--gutter`）。Material 3 の compact の 16dp と一致する。
- ○× のマスは 83×72〜76px（375 では 78×72）。主ボタンは高さ 56px、フッターのリンクは高さ 56px。いずれも 44／48 を満たす。44 未満は店名のリンクだけ。
- 余白の値はどれも 4 の倍数（4／8／12／16／24／32／48／72）。トークン（`tokens.css` の `--space-*`）は守られている。問題は値の倍数ではなく、指摘2・3の配分。
- 節の中の近接の順は正しい（h2 から最初の行まで 24px ＜ 行の間 49px ＜ 節の境 168px）。
- ○× の数は `openStarts` から出していて、表示と一致する（9マス中、空き3、数は 4／2／3）。
- 本文 18px と行間 1.9（34.2px）は `PLAN.md:51` どおり。
- 写真は PC だけに出し、スマホでは `display:none`（`top.css:127`）。これは `PLAN.md:33`（写真は下げる）と合っている。ただしその結果、スマホの最初の画面には色の面が薄緑の台1つしか無く、PC で写真が担っていた「格」の役は、スマホでは見出しにしか残っていない。指摘1が効くのはこのため。
