# 独立レビュー：高齢の利用者本人の視点（70代後半・八王子・一人暮らし・老眼・指先が乾く・PC は息子の家で）

実施 2026-10-22 夜（試験の時刻が 23 時台のため、「今日」の枠はすべて受付終了になっている。これは時刻による正常な表示）。
配信 `python -m http.server 8796`（終了済み）。Playwright（chromium-1234）、deviceScaleFactor 1。
測定スクリプトは scratchpad の `senior.mjs`（流れの撮影と測定）・`senior2.mjs`（最初の画面と固定部の寸法）・`senior3.mjs`（PC でホイール、headed）・`senior4.mjs`（null の再現・既定の選択・決済画面の戻る）。生の測定値は scratchpad の `senior-measure.json`・`an.txt`（セッションの終了で消える。要点はこの文書に写した）。

照らした基準
- WCAG 2.2（= JIS X 8341-3:2016 が参照する達成基準と同じ番号）：1.4.3 コントラスト（最低）4.5:1、1.4.6 コントラスト（高度）7:1、1.4.4 テキストのサイズ変更、2.5.8 ターゲットのサイズ（最低）24×24 CSS px（AA）、2.5.5 ターゲットのサイズ（高度）44×44（AAA）
- Apple Human Interface Guidelines：押せる所は 44×44 pt 以上
- Material Design：48×48 dp 以上、隣との間隔 8 dp 以上
- デジタル庁デザインシステム：本文の文字は 16px 以上を推奨
- Nielsen Norman Group「Usability for Senior Citizens」（高齢者の調査報告）：小さい文字・小さい的・画面外の大事な物に気づかない、を高齢者の失敗の主な原因として挙げる
（文言の引用はしない。番号と趣旨のみ）

## 指摘（重い順）

### 1. 重大：確認の画面に「null」という英字が出る（お金を払う直前）
- 場所：手順4「この内容で予約します」。`js/booking.js:431` と `:438-439`
- 原因：`readoutOf()` は、ご要望が空の時に配列へ `null` を入れ、`renderConfirm()` は担当を指名した時に `extra = null` にする。`h()` は null を捨てるが、`replaceChildren(...readoutOf(draft), extra)` は null を文字列「null」として入れる
- 再現（実測、`senior4.mjs`）：
  - 「どなたでも」＋ご要望が空 → 連絡先の下に「null」（`senior-390-08-step4-full.png`、`senior-390L-08-step4.png`）
  - 山本を指名＋ご要望が空 → `#readout` の子が `P,P,P,TEXT[null],P,TEXT[null]`、「null」が2つ（`senior-390-08b-step4-named-nonotes.png`）
  - 山本を指名＋ご要望あり → 末尾に「null」が1つ
  - 「null」が出ないのは「どなたでも」＋ご要望ありの時だけ。既存の `check.mjs` は「見本の内容を入れる」（ご要望が入る）と「どなたでも」の組だけを通るので、この不具合を通してしまっていた
- この人に起きること：ご要望は「なくてもかまいません」と書かれているので空のまま進むのが普通。支払いボタンのすぐ上に意味の分からない英字が出て「何か壊れた」「間違ったお金を取られるかも」と手が止まり、閉じてしまう。家族に電話して聞く
- 直し方：`replaceChildren(...[...readoutOf(draft), extra].filter(Boolean))`。または `readoutOf` の行を `h("div",…)` で包む。試験に「ご要望が空」「担当を指名」の組を加え、`#readout` の textContent に "null" が無いことを確かめる

### 2. 中：手順1・手順2で、次に押すボタンや時刻が最初の画面に見えない
- 手順1「利用時間を選んでください」（主ボタン「この利用時間で進む」）。2時間が既定で選ばれている（`2:true`）ので押せば進めるが、ボタンの位置は
  - 390×844 標準：ボタン上端 777、デモ帯の上端 808 → 見えるのは 31px だけ（56px の半分強）。帯の下に隠れて「切れた緑の帯」に見える
  - 390×844 大きく：上端 908 > 帯 804 → 0px
  - 375×667 標準：上端 799 > 帯 631 → 0px（`senior-375-02-step1.png`、4時間の札も途中で切れる）
- 手順2「担当と日時を選んでください」：到着時、最初の時刻の行は主ボタン欄（dock）の後ろ
  - 390×844 標準：最初の時刻の上端 704、dock 上端 731（`senior-390-03-step2.png`。見出し「10月23日(金)の開始時刻」の下に○の上端がわずかに覗くだけ）
  - 390 大きく：時刻 830 / dock 719、375×667：時刻 703 / dock 554 → 時刻は1行も見えない（`senior-390L-03-step2.png`・`senior-375-03-step2.png`）
  - 下へ動かした後も、上の固定（手順の帯 61px）と下の固定（dock＋デモ帯）が画面を取り、時刻に使える高さは 375×667 で 348px（画面の 52%）、375×667 大きくで 310px（46%）。時刻の行は 70〜72px なので4行ほど
- この人に起きること：画面の一番目立つ物が灰色の「この時間で予約する」。時刻を選ぶ所があることに気づかず、灰色のボタンを押す。押すと赤字の案内が出て時刻の所へ動く（`senior-390-04-step2-noslot.png`）ので行き詰まりはしないが、「間違えた」と感じる最初の場面になる。NN/g の高齢者の調査が挙げる「画面の外にある物に気づかない」に当たる
- 直し方の案：
  - 手順1：ボタンを札の直後でなく、帯の上に固定する（手順2と同じ dock を手順1にも使う）か、札の説明文を短くして 390 標準で収める
  - 手順2：時刻をまだ選んでいない間は、dock に「下の時刻から1つ選んでください ↓」の文を置き、灰色のボタンは出さない（または時刻を選ぶまで dock を出さない）。日付を選んだら時刻の見出しまで自動で送る

### 3. 中：「文字の大きさ」の切替と、お金・時間の注意書きが 15px（大きくしたい人が読めない所に切替がある）
- 実測（標準）：「文字の大きさ」「標準」「大きく」15px。手順4の「お支払いが15分以内に終わらない時は、この枠をほかの方に空けます。」15px・色 `--mute`（4.9:1）。決済の画面の「午後11時22分までにお支払いがないと…「戻る」を押すと仮の予約を取り消し…」15px（5.5:1）。完了・決済の項目名「予約番号」「日時」「担当」「金額」15px。手順2・3の上の「利用時間：2時間」「担当：…」「日時：…」15px
- 大きくにしても縮まない 14px（rem 固定）：トップの「今日」「明日」「あさって」（`css/top.css:70`）、「空きなし」（`css/top.css:109`）、トップの店名（390 幅、`css/top.css:12`）、手順2の円の中の「指名 なし」（`css/pages.css:124`）。大きくの時の測定でもこの4つは 14px のまま
- 基準：デジタル庁デザインシステムの本文 16px 以上。NN/g は高齢者に小さい文字を避けるよう求める。コントラストは全て 4.5:1 以上で WCAG 1.4.3 は満たすが、1.4.6（7:1）は 15px の注記の多く（4.9〜5.5:1）で満たさない
- この人に起きること：老眼で「文字の大きさ」の字そのものが読みにくく、切替に気づかない。お金に関わる「15分」「午後11時22分まで」を読み落とし、後で「枠が無くなった」と慌てる
- 直し方：`--fs-small` を 16px（1rem）以上にする。注意書きのうちお金・期限に関わる2つは `--fs-body`・`--ink` に上げる。0.875rem の4か所は `var(--fs-small)` に寄せ、大きくで一緒に大きくなるようにする

### 4. 中：完了の画面で「×」と「この枠は予約できなくなりました」を見せる
- 場所：完了「ご予約を承りました。」の下。`js/booking.js:569-573`（`senior-390-10-done-full.png`）
- この人に起きること：払った直後に灰色の ×・「予約済み」・「予約できなくなりました」が並ぶ。慎重な人は「予約できなかった」「払ったのに取れていない」と読む。これは提案先（お店）に仕組みを見せるための部品で、お客様向けではない
- 直し方：お客様の完了画面からは外し、「当日の流れ（お伺いの前にお電話します）」「取り消したい時の連絡先」「この画面を残しておく方法（写真に撮る・印刷）」に置き換える。お店向けの見せ方は管理画面か「このデモについて」へ移す。同じ画面の「管理画面を見る」も、お客様には意味が分からない言葉

### 5. 中：PC（1440）で日にちの帯が、マウスのホイールで横に動かない
- 場所：手順2の日にちの帯 `#date-strip`、`css/base.css:409`（`scrollbar-width: thin`）
- 実測（`senior3.mjs`、表示ありの Chrome）：帯の上でホイールを 300 回すと、帯の scrollLeft は 0 のまま、ページが 300px 下へ動いた。帯の横のスクロールバーは高さ 10px。14日のうち最初に見えるのは5日と6日目の一部（`senior-1440-03b-step2-headed.png`）
- 案内は「横に動かすと先の日も見られます」で、スマホの指の操作を前提にしている
- この人に起きること：息子の家の PC で一緒に見る時、来週の日を出せない。10px の細い棒をつかむのは乾いた指のマウス操作ではまず無理。Material の 48dp、WCAG 2.5.5 の 44px に遠く届かない的
- 直し方：帯の左右に「前の日」「次の日」のボタン（56px 以上）を置く。PC 幅では帯を折り返して 14 日を2段で全部見せる、でもよい

### 6. 軽微：入力の誤りで、最初の欄だけ枠が赤くならない
- 場所：手順3 で未入力のまま「入力内容を確かめる」。`css/base.css:556` の `.input:focus-visible { border-color: var(--sugi) }` が `:265` の `.input[aria-invalid="true"]` の赤を上書きする（同じ詳細度で後に書かれている）
- 実測：「お名前」は濃緑の二重枠、「電話番号」「ご住所」は赤枠（`senior-390-07-step3-errors.png`）。下の赤字の案内は出ている
- この人に起きること：「お名前は合っていて、電話番号が違う」と読み違える
- 直し方：`.input[aria-invalid="true"]:focus-visible { border-color: var(--alert) }` を足す

### 7. 軽微：予約の画面で、390 幅だと店名が消える
- 場所：`css/pages.css:33`（419px 以下で `.topline__shop { display: none }`）。手順1の「トップへ」も手順2以降は「戻る」になる
- この人に起きること：「まだ同じお店のページにいるのか」の手がかりが無くなる。家族に勧められたサイトかどうかを店名で確かめたい人には不安
- 直し方：店名を「文字の大きさ」の左に短くして残す（トップでは 14px で残している）か、手順の帯に小さく出す

### 8. 軽微：分からない言葉
- 1画面に出る外来語・専門語：「Stripe」「テスト決済」（決済の画面、`js/booking.js:531`）、「デモ」（下の帯に常時）、「枠」（トップ「4枠」、手順4・決済「この枠を」）、「指名なし」、「管理画面」（完了の画面）
- 「Stripe」は本番では出ない画面だが、この人がデモを触るなら意味が分からない。「枠」は「空いている時刻」と言い換えられる（トップの注記も「始められる時刻の数」と書いている）

### 9. 軽微：トップの空き表で、隣の○の間が 5px
- 場所：トップ「今日から3日間の空き」の○のリンク（`js/top.js:53`）。各 83×76px で WCAG 2.5.8・HIG・Material の大きさは満たすが、森田の 23日と 24日の○は横の間隔 5px（Material の 8dp に足りない）
- 押し間違えても次の画面で日にちを選び直せるので軽い。間隔を 8px 以上にする

## 実データで確かめて合っていたこと
- コントラスト：4画面幅 × 10画面の目に見える全ての文字で、最低 4.9:1（`--mute` on 薄緑）。4.5:1 未満は 0 件（WCAG 1.4.3 / JIS X 8341-3 を満たす）
- タップ領域：主ボタン 56px（大きく 64px）、時刻の行 358×70、日にちの札 72×153、担当の札 84×100、文字の大きさの切替 48px（大きく 56px）。44px 未満は店名リンク（27px、高さ）と「見本の内容を入れる（デモ用）」（29px）の2つだけで、どちらも WCAG 2.5.8 の 24px は満たす
- ○×は色だけでなく「空き」「予約済み」「時間が足りません」「受付終了」の文字が付く。選んだ時刻の行には「選択中」と終わりの時刻「午後2時まで」が出て、dock に「10月23日(金) 午後0時〜午後2時 担当：山本」が出る
- 時刻を選ばずに灰色のボタンを押しても、赤字の案内（18px・6.8:1）が出て時刻の所へ動く。行き詰まらない
- 手順3 の未入力の案内は欄ごとに赤字 18px＋左の赤線、最初の欄へフォーカス
- 確認の画面は表ではなく「〜がお伺いします。お伺い先は〜のお宅です。」の文で読める（null を除けば、この人に一番分かりやすい形）
- 4つの幅すべてで横スクロールなし。ページの error は 0 件
- 決済の画面の「戻る」は確認の画面（#step-4）へ戻り、そのことは画面に書いてある

## 良くできていて変えない方がよい所
1. 確認の画面を文章で書く形（「10月23日(金)の午後0時から午後2時まで（2時間）、山本 さち子がお伺いします。」）。読み上げても紙で読んでも同じに分かる
2. トップの最初の画面に「文字の大きさ 標準／大きく」があり、選んだ大きさを次の画面へ持ち越す（読み込み前に適用し、瞬きが無い）
3. 時刻の行が 70px と大きく、×の行は枠を消して押せないことを形でも示す。○×に必ず文字が付く
